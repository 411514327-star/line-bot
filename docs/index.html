LINE 群組相簿 Bot（改善版）

針對 LINE 群組相片易被文字洗版、下載過期失效之痛點，使用 FastAPI、LINE Messaging API SDK v3 與 Cloudflare Tunnel 打造之智慧相簿機器人。具備群組照片自動存檔、自訂天數輪播回顧、健全防呆校驗與聊天場景安全隔離機制。

前往 GitHub 專案儲存庫 瀏覽實測截圖與證明
🎯 專案用途與目標
在社團、家庭或朋友群組中，相片常被後續大量文字訊息洗版淹沒。本 Bot 能於後台自動保存群組發送之相片，隨時供成員以卡片形式回顧近期回憶。
👥 目標使用對象
日常熱絡的 LINE 多人聊天室、社團活動群組、旅遊出遊群組，以及需要定時回顧群組日常相片之成員。
💡 解決的核心問題
解決相片下載過期失效、找舊照需翻找聊天紀錄的困擾；並透過改善版解決語音/貼圖已讀不回、指令輸入錯誤無提示等互動缺陷。
✨ 五大核心功能與指令範例
從第一版基準至改善版，落實模組化設計與健全防呆驗證
📸
1. 群組相片自動儲存
群組成員發送相片時，Webhook 自動觸發 ImageMessageContent，透過 LINE Messaging Blob API 下載相片並儲存至本機，SQLite 資料庫自動記錄群組 ID 與時間。回覆確認訊息：
📸 照片已成功儲存到群組相簿！
🎠
2. 智慧 Flex Carousel 輪播回顧
支援指定天數回顧與預設回顧：
  • 回顧：預設撈取過去 7 天照片。
  • 回顧 3：動態撈取過去 3 天照片。
  • 回傳精美輪播卡片，顯示日期時間並支援點擊檢視原圖。
🛡️
3. 健全輸入檢查與格式防呆
徹底消除無效指令與操作疑惑：
  • 純空格/空白訊息：提示勿傳送純空白，並給予功能範例。
  • 無效天數（如 回顧 abc、回顧 0）：主動提示輸入數字，並給出 回顧 3 等範例。
💬
4. 不支援輸入與未知文字引導
消除「已讀不回」的負面體驗：
  • 傳送貼圖、影片、語音、位置：提示目前僅支援相片，並引導輸入「說明」。
  • 未知文字（如 哈囉）：不再無意義 Echo，而是提示無法辨識並引導「說明」。
🔒
5. 聊天室場景防護（群組限定）
群組相簿具備群組共享特質。若使用者於一對一私聊傳送照片或輸入「回顧」，Bot 主動攔截並提示：
⚠️ 本相簿功能僅支援在群組中使用，請將我加入群組後再傳送照片喔！，確保相簿資料隔離與正確歸屬。

🛠️ 使用的 AI 工具與協作模式
採用 Google Antigravity AI Coding Assistant 進行結對編程（Pair Programming）。由人類開發者主導架構決策與實機測試，AI 負責程式碼重構、Flex Carousel 模板構建、Git 版本控管及自動化文件排版。
💬 代表性提示詞指令 (Prompt)
作業要比較「改善前後」，請拆成三次 commit： - Commit 1（第一版基準）：收群組照片並存檔、「回顧」輪播（固定 7 天）、「說明」。先不做輸入檢查和不支援輸入處理。 - Commit 2（改善版）：輸入檢查、不支援輸入提示、「回顧 天數」、一對一聊天提示。 - Commit 3：文件（README、test-log、project-plan、.env.example）。 每次 commit 前先告訴我要測什麼，我實測後再 commit。
🔍 檢查與修正 AI 產出的關鍵經驗（自我校正紀錄）
在本次專案協作中，有兩次非常關鍵的檢查與校正過程：
  1. 專案起點校正：初次分析儲存庫時，發現舊有代碼為先前課堂練習的「BMI 計算器」。AI 主動向開發者提出差異警告，開發者即時確認「BMI 僅為先前測試練習，非本次作業」，指示 AI 徹底移除 BMI 相關代碼，從頭建立全新群組相簿 Bot，避免將錯誤基礎納入版本控制。
  2. 客戶端環境限制確認：在測試 2-1「空白輸入檢查」時，開發者實測發現 LINE App 手機端在文字框僅有空格時，原生發送按鈕會呈現灰色禁用狀態，導致實機無法傳送純空格。AI 與開發者確認此為「行動客戶端原生限制」，決定於測試紀錄表中如實記載「無法實測（前端限制）」，同時後端仍保留嚴密的防禦校驗邏輯，展現誠實且具工程嚴謹性的測試態度。
  3. 資安與機密保護：嚴密檢核 Git 提交流程，要求簡報暫存檔與本地照片不進 Git，且 .env 金鑰僅存本機，遠端儲存庫僅保留 .env.example，完全符合資安規範。

💡 學習心得與已知限制
反思開發歷程之收穫與系統邊界
🎓 學習收穫與心得
1. LINE Messaging SDK v3 架構掌握：深入理解 Webhook 事件分發機制（MessageEvent、ImageMessageContent）及非同步 Web 框架 FastAPI 的結合運用。
2. 防呆與人機互動設計：認識到良好對話體驗不僅在於「主功能可用」，更在於「異常輸入時的引導閉環」——消除已讀不回，以清晰提示指導使用者。
3. 版本控管實務：學會以清晰的 Commit 脈絡展示軟體迭代歷程（基準版 ➔ 改善版 ➔ 文件交付），奠定良好工程習慣。
⚠️ 系統已知限制與後續改進方向
1. 公網 HTTPS 依賴：LINE Flex 圖片加載必須具備有效 HTTPS 網址，本機測試需依賴 Cloudflare Tunnel；若後續部署至雲端 PaaS（如 Render / Railway），將可獲得固定永久域名。
2. Flex Carousel 卡片上限：LINE API 規定單則 Carousel 訊息上限為 10~12 張 Bubble，照片過多時需導入分頁或篩選機制。
3. 相簿持久化儲存：目前採用 SQLite 本地檔案，未來若有多伺服器負載平衡需求，可考慮遷移至 S3 / Cloudinary 雲端物件儲存。
