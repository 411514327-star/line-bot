專案概要

做什麼：把 LINE 群組變成朋友的共享相簿。大家在群組傳照片，Bot 自動存下來；輸入「回顧」用輪播卡片看最近幾天的照片。靈感來自 Retro（Photos with Friends）的「小圈子、低壓力分享」。

指令：說明、回顧（最近 7 天）、回顧 N（最近 N 天）。

技術：Python、FastAPI、line-bot-sdk、SQLite、Flex Message Carousel、cloudflared tunnel。

先說明一件事：第一版 Bot 當時沒有上傳到 GitHub，所以這次先重建一個「基準版本」放上去，再逐步改善。這個紀錄中的「第一版」指的就是這個基準版本。作業之前倉庫裡的 BMI 範例只是用來測試 GitHub，與本專案無關。

第三輪：改用 OpenCode 修正

老師口頭提到可以用 OpenCode 搭配開源模型來修 Bot。這次我在自己的電腦安裝 OpenCode，使用它內建的免費模型（Big Pickle）。

如實說明：老師有提到可以在 notebook 上跑開源模型再連接，這一次我沒有這樣做，而是直接用 OpenCode 內建的免費模型。

做法

  1. 先切到唯讀的 Plan 模式，請它閱讀 main.py（並明確要求不要讀取 .env），列出可以改善的地方。它列出 10 項錯誤處理與一些程式整理建議。
  2. 我挑選 4 項小而風險低的修改，其餘暫不處理：
    • 照片下載與存檔加上錯誤處理，失敗時提示重傳，不讓整個 webhook 回 500。
    • 防止 LINE 重送訊息造成同一張照片重複寫入。
    • 啟動時如果 BASE_URL 不是 https，印出警告。
    • 移除提示文字中多餘的反引號（第二版測試時發現）。
  3. 切到 Build 模式修改；它回報修改了 5 處並做了語法檢查，沒有自己 commit。
  4. 我先確認 git status 只有 main.py 被改，再重啟伺服器，在 LINE 實測，通過後才 commit 並 push。

為什麼不全改

把 callback 拆成多個函式等大改動，容易改壞已經測好的功能，也會讓前面的測試紀錄失效，所以列為未來改善。

修改後實測：傳照片正常、回顧 abc 的提示不再有反引號、回顧 3 輪播正常。

沒有實測的部分：照片下載失敗的提示、LINE 重送時不重複寫入、BASE_URL 非 https 的警告。這些很難在 LINE 上人為製造，所以只做了程式修改，不能算通過。

遇到的問題與解法

問題解法
LINE 後台頁面很多，找不到 Messaging API 設定從 Official Account Manager 的設定進入 Messaging API 頁面，才能取得 channel 資料
cloudflared 免費網址每次重開都會變網址變了就同時更新 .env 的 BASE_URL 和 LINE 的 Webhook 網址，並重啟伺服器
一次貼三行指令，Bot 當成一個指令每則訊息要單獨送出；記為已知限制
提示文字出現反引號（LINE 不會渲染 Markdown）測試時發現，第三輪由 OpenCode 移除
PowerShell 擋住 npm 腳本以 Set-ExecutionPolicy -Scope CurrentUser RemoteSigned 放寬目前使用者的限制
重新啟動時缺少套件（No module named 'dotenv'）執行 python -m pip install -r requirements.txt
截圖檔名變成 .png.jpg、截圖含有真人姓名統一改成 .jpg；含姓名的那張已從最新版專案移除（Git 歷史紀錄中仍留有舊版），其他截圖未拍到人臉

已知限制與未來改善

  • 免費 tunnel 沒有穩定性保證，網址會變；正式使用需要固定網址的雲端部署。
  • 照片存在本機，沒有備份。
  • 測試照片都是同一天，依天數過濾還沒有實機證據。
  • 多行訊息會被當成同一個指令。
  • 未實測：純空白、影片、語音、下載失敗、重複寫入。
  • callback 函式偏長，之後可拆成多個處理函式，並補上正式的 logging。
  • 想做的功能：週日自動推播回顧、月回顧拼貼圖、Rich Menu 按鈕。
